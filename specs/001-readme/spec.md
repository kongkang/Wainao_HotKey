## User Scenarios & Testing *(mandatory)*

### User Story 1 - 长按 Command 查看当前可用快捷键 (Priority: P1)

作为重度 macOS 用户，我希望长按 Command 键时能立即看到当前应用与焦点可用的快捷键列表，以便在不离开当前上下文的情况下确认操作方式。

**Why this priority**: 这是工具的核心价值主张，直接解决用户对“当前我能用哪些快捷键”的即时需求，决定了产品的首次使用体验。

**Independent Test**: 在目标机器上授予所需权限后，长按 Command 键，观察是否在 1 秒内弹出浮动层且信息与当前应用上下文匹配。

**Acceptance Scenarios**:

1. **Given** 用户已授予必要的辅助功能权限且桌面上有前台应用，**When** 用户长按 Command 超过设定阈值，**Then** 浮动层在 1 秒内出现并展示当前应用与焦点的快捷键清单。
2. **Given** 浮动层已显示快捷键清单，**When** 用户松开 Command 键且未进行任何操作，**Then** 浮动层自动关闭且不触发任何原有快捷键动作。

---

### User Story 2 - 打开稳定窗口管理全局快捷键索引 (Priority: P2)

作为需要整理快捷键的用户，我希望从浮动层或菜单进入一个稳定窗口，集中浏览、搜索并管理所有系统与应用快捷键，以便识别冲突和来源。

**Why this priority**: 稳定窗口承载长期管理需求，是浮动层之外的第二个主要入口，对持续价值和深度使用至关重要。

**Independent Test**: 从浮动层点击任意快捷键或通过应用入口打开稳定窗口，验证是否可以检索各个来源的快捷键信息并查看详细上下文。

**Acceptance Scenarios**:

1. **Given** 用户在浮动层中点击某一快捷键条目，**When** 系统切换到稳定窗口，**Then** 稳定窗口应展示该条目的完整信息（来源、菜单路径、可编辑性）并允许搜索其他条目。
2. **Given** 稳定窗口已加载索引，**When** 用户按关键词搜索某快捷键组合或应用名称，**Then** 搜索结果仅展示匹配条目并允许用户按来源或冲突状态过滤。

---

### User Story 3 - 识别并处理快捷键冲突 (Priority: P3)

作为需要排查快捷键冲突的用户，我希望系统能够自动标记相同组合被多个主体占用的情况，并指导我进一步处理或跳转到相关设置页面。

**Why this priority**: 虽然相较即时查看略次要，但冲突检测是统一管理工具的重要差异化能力，能显著提升用户感知价值。

**Independent Test**: 构造至少两个来源使用同一快捷键的环境，扫描后确认系统识别冲突并在稳定窗口或浮动层中清晰标记。

**Acceptance Scenarios**:

1. **Given** 系统索引中存在两个不同来源注册了相同的标准化组合，**When** 用户查看该组合，**Then** 条目上应有冲突标记并提示涉及的主体。
2. **Given** 用户在冲突条目详情页，**When** 系统检测到其中一个条目无法直接修改，**Then** 应提供跳转至对应系统或应用设置页面的指引。

---

### Edge Cases

- 当用户长按 Command 的同时快速触发其他快捷键时，系统需忽略该次触发，保证原生快捷键行为不受干扰。
- 未授予辅助功能或读取权限时，系统需给出明确提示，并在权限恢复后自动重试扫描。
- 当前台应用没有可用快捷键（如纯文本输入框）时，浮动层需显示无匹配提示并提供跳转至稳定窗口的选项。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统必须在检测到用户长按 Command 超过设定阈值时，在 1 秒内显示包含当前应用名称、窗口标题与焦点类型的浮动层。
- **FR-002**: 浮动层必须列出当前上下文可用的快捷键条目，包含组合键、人类可读描述、来源类型，并按系统 > 应用 > 网页的优先级排序。
- **FR-003**: 浮动层必须提供显式操作（例如点击）以打开稳定窗口，并将所选快捷键上下文传递给稳定窗口作为初始视图。
- **FR-004**: 系统必须在稳定窗口中展示全量快捷键索引，支持按应用、来源、冲突状态与可编辑性进行搜索与过滤。
- **FR-005**: 系统必须执行只读扫描以采集系统、应用、自定义菜单及网页扩展的快捷键信息，并将组合键标准化为统一格式。
- **FR-006**: 系统必须识别并标记冲突组合，按同一应用内、跨应用、系统 vs 应用等等级分类，并在界面中清晰展示。
- **FR-007**: 系统必须提供导出功能，使用户能够将当前索引（含冲突标记与来源）导出为通用格式以供备份或分享。
- **FR-008**: 在尝试读取或展示快捷键信息前，系统必须检测必需权限状态，未授权时引导用户完成授权并记录失败原因。
- **FR-009**: 稳定窗口必须允许用户跳转至对应系统或应用的快捷键配置入口，对不可直接修改的条目提供操作指引。

### Key Entities *(include if feature involves data)*

- **快捷键条目（Shortcut Entry）**: 表示单个快捷键组合的标准化记录，包括原始组合、规范化组合、触发目标、来源类型、所属主体及是否可编辑。
- **冲突分组（Conflict Group）**: 将使用同一规范化组合的多个快捷键条目聚合，记录冲突等级与涉及主体，供界面高亮与筛选使用。
- **上下文状态（Context Snapshot）**: 表示当前前台应用、窗口标题与焦点元素类型，用于决定浮动层展示的快捷键列表及排序。

## Assumptions

- 初始版本面向 macOS 13 及以上版本，默认用户具备安装第三方辅助工具的权限。
- 浏览器层数据通过官方扩展接口或现成插件提供，暂不涉及非标准或越权采集方式。
- 默认用户对所有受管应用拥有读取偏好设置的本地权限，企业环境中的受限权限需后续版本支持。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在可用权限就绪的前提下，95% 的长按 Command 操作在 1 秒内展示浮动层且信息与当前应用一致（通过可重复测试验证）。
- **SC-002**: 首次全量扫描完成后，索引覆盖率需达到目标测试清单中已知快捷键的 90% 以上，并在 3 分钟内完成。
- **SC-003**: 体验测试中，80% 的目标用户能在稳定窗口中 30 秒内定位一个指定的快捷键来源或冲突。
- **SC-004**: 封闭测试期内，与快捷键冲突相关的用户反馈或支持请求数量相较基线下降 40%，表明工具有效缓解冲突识别难题。
- **SC-005**: 至少 85% 的测试用户表示浮动层信息可读性良好，并愿意在日常工作中继续使用该功能（通过调查问卷量化）。
